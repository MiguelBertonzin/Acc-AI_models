Quantização manual da entrada:

  imagem_float = imagem_uint8.astype(float32) / 255.0
  entrada_int8 = round(imagem_float * 64)

  logits_float = saida_int8.astype(float32) / 4.0
  predicao = argmax(logits_float)

Como dividir todos os logits pela mesma constante não muda o argmax, também
é válido calcular argmax diretamente sobre a saída int8.

8. AMOSTRAGEM IDÊNTICA À CPU E GPU
======================================================================

Seed global:

  20260825

Tamanhos:

  N = 100
  N = 1.000
  N = 10.000

Os subconjuntos devem ser balanceados, aninhados e determinísticos.

Algoritmo usado em CPU/GPU:

  labels = labels.reshape(-1)
  rng = numpy.random.default_rng(20260825)
  groups = []

  para class_id de 0 a 9:
      idx = índices em que labels == class_id
      rng.shuffle(idx)
      groups.append(idx)

  stratified_order = numpy.stack(groups, axis=1).reshape(-1)

  selected_N = stratified_order[:N]

Isso produz alternância entre classes e garante:

  100: 10 imagens por classe
  1.000: 100 imagens por classe
  10.000: 1.000 imagens por classe

Os conjuntos são aninhados:

  conjunto 100 contido no conjunto 1.000
  conjunto 1.000 contido no conjunto 10.000

Salvar:

  results/indices/indices_n100.npy
  results/indices/indices_n1000.npy
  results/indices/indices_n10000.npy

Ordem de cada passagem:

  rng = numpy.random.default_rng(seed + N * 1009)
  permutations = [rng.permutation(N) para cada ciclo]

Usar exatamente essa regra para ficar alinhado com CPU/GPU.

Dentro do tempo total da passagem:

  selecionar próxima imagem já quantizada;
  copiar para o input buffer do runner, se necessário;
  execute_async;
  wait;
  ler a saída int8;
  dequantizar ou calcular argmax diretamente;
  armazenar predição;
  executar o laço Python serial.

Fora:

  carga do XModel;
  leitura do arquivo NPZ;
  quantização prévia do dataset;
  warm-up;
  checkpoint.

Fórmula por passagem:

  FPS_passagem = N / tempo_de_parede_da_passagem

FPS global:

  FPS_global = total_de_imagens / soma_dos_tempos_das_passagens

Não calcular FPS global como média aritmética dos FPS.

Esse é o cenário principal para comparar com:

  CPU/GPU:
    laço Python + batch/tensor + inferência + sincronização + argmax

  hls4ml:
    cópia de entrada pré-empacotada + DMA/FPGA/DMA + decode + argmax

As fronteiras físicas ainda são diferentes e devem ser declaradas.

  medir overhead do sampler;
  potência dinâmica = max(ativa - idle, 0);
  energia por imagem = potência ativa / FPS_global;
  energia dinâmica por imagem = potência dinâmica / FPS_global.

Arquivos:

  power_idle_raw.csv
  power_samples_n100.csv
  power_samples_n1000.csv
  power_samples_n10000.csv

Se 12V_power não existir:

  não escolher outro rail silenciosamente;
  documentar todos os rails;
  explicar a diferença física;
  produzir desempenho sem energia até resolver a telemetria.
